# Live Evolution 콘솔 — 사용 가이드

> 화면 안 도움말(각 화면 상단의 **❓ 이 화면 사용법**)의 확장판입니다.
> 실행·설치는 `README.md`, 1세대 리허설 실측 기록은 `RUNBOOK_진화1세대.md` 참고.

## 이 콘솔이 하는 일 (한 문단)

concentration-cube 의 판정 엔진은 "집중/이탈/멍때림"을 파라미터(임계값·가중치)로 구분합니다.
이 콘솔은 ① 사람이 실시간 지시로 **정답지**를 만들고, ② 정답지와 판정이 어긋난 **오답노트**를
증거로 AI 에이전트에게 개선안을 만들게 하고, ③ 숨겨둔 시험지(holdout)로 **게이트 시험**을 통과한
개선안만 ④ **사람이 [채택]** 해서 운영 기준을 교체하는 — "임상 검증 게이트형 자가진화"의
조종석입니다. 자동은 제안·시험까지, 채택은 언제나 사람입니다.

## 용어 사전 — 이것만 알면 전 화면이 읽힙니다

화면 어디서든 <u>점선 밑줄</u> 용어를 클릭하면 같은 설명이 뜹니다 (상단 배너 📖 용어 = 전체 보기).

| 용어 | 쉬운 뜻 |
|:--|:--|
| **세션** | 측정 1회 — [시작]부터 종료까지 기기가 눈 움직임을 기록한 "한 판" (검증 세션 = 5분) |
| **정답지** (= 라벨) | 측정 중 관리자가 "지금 실제 상태"를 버튼으로 기록한 것. 기계 판정을 채점하는 기준. 저장 후 수정 불가(세션당 1회) |
| **연습용 (train)** | AI에게 보여주는 정답지 묶음 — AI는 이것만 보고 개선안을 연습 |
| **시험용 (holdout)** | AI에게 절대 안 보여주는 정답지 묶음(약 1/4, 자동 배정) — 개선안의 "진짜 실력" 측정용. 사람이 고를 수 없음(공정성) |
| **판정 기준 (param_set)** | 집중/이탈/멍때림을 가르는 숫자들. 진화가 개선하는 대상 (v1.0 → v1.1-gen1 …) |
| **세대** | 개선 시도 1회 = 증거 수집 → AI 제안 → 게이트 시험 → 채택/기각 한 바퀴 |
| **게이트** | 채택 후보의 자동 합격선: 시험용에서 어떤 상태도 2%p 넘게 나빠지지 않고 표적 상태는 개선 |
| **민감도** | 실제 그 상태였던 구간 중 기계도 맞힌 비율 (놓치지 않는 능력) |
| **특이도** | 그 상태가 아닌 구간을 아니라고 본 비율 (오인하지 않는 능력) |
| **10초 구간 (bin)** | 채점의 최소 단위 — 5분 세션 = 30개 구간 |
| **오답** | 정답지와 기계 판정이 어긋난 10초 구간 (오답노트의 재료) |
| **채택 (promote)** | 통과한 개선안을 실제 기준으로 확정하는 사람의 결정 — 전 세션 재채점 + 즉시 적용 |
| **연구 제외** | 실수한 세션을 평가에서만 빼기 — 삭제 아님, 복원 가능 |
| **측정 낮음 (invalid)** | 얼굴/시선을 못 읽은 구간 — 이탈로 세지 않고 채점 제외 |

## 시작 체크리스트 (매 작업일)


## 메뉴별 상세

### ② 대시보드 `/`
**언제**: 접속할 때마다 첫 화면. **무엇을**: 연결 3장 + 진행 중 루프 + 알림 + 최근 세대.
- 카드가 빨간불이면 그 카드의 안내대로 해결하는 게 최우선입니다 (죽은 화면은 없고, 데이터
  영역에 연결 안내가 뜹니다).
- 🔔 "제안 준비됨" = 새 정답지가 N개(설정) 쌓였다는 뜻 — 진화를 돌릴 타이밍.
- ⚠ "연속 기각 3세대" = 파라미터 튜닝의 한계 신호 — 피처/규칙 재설계(레벨 2) 검토를 권합니다.

### ③ 에이전트 연결 `/agent`
**언제**: 최초 1회 + 로그인 만료 시. **무엇을**: Claude Code/Codex 감지 → 인증 확인 → 기본 지정.
- 인증 확인은 실제 미니 호출이라 **첫 회 40초~2분**. 실패로 뜨면 [터미널 열기] → 로그인 →
  [다시 확인] 순서.
- 구독(로그인)은 PC 의 CLI 에 있는 것을 그대로 씁니다 — 이 콘솔에 키를 넣지 않습니다.

### ④ 검증 세션 콘솔 `/console` — 매일 쓰는 화면
**언제**: 정답지를 만들 때(권장: 하루 5분×2~3회). **무엇을**: 기기 시작 + 지시 마킹 + 저장.
1. 프리셋·라벨러 선택 → **[시작]** (기기 보정부터 자동 진행)
2. 안내판이 "다음 지시 + 카운트다운"을 크게 표시 — **말로 지시하며 동시에 버튼 클릭**
   - [집중] [멍때리기] [이탈] = 지시한 상태 / [중단/기타] = 화장실·방해 (정답지 공백 처리)
3. 5분 후(또는 [세션 종료]) → 요약 확인 → **[저장]** (1회·불변) 또는 [연구 제외]
- 실수했으면 고치려 하지 말고 **버리고 다시** — 5분이라 싸다는 것이 이 설계의 핵심입니다.
- 동기화 경고 배지가 있으면 저장 전에 타임라인을 꼭 확인.

### ⑨ 아카이브 `/archive`
**언제**: 세션을 열람·점검할 때, 실수 세션을 제외/복원할 때. **무엇을**: 전 세션 영구 보관 열람.
- 행 클릭 → 판정 vs 정답지 나란히 + **세대별 재채점 비교** ("엔진이 점점 잘 읽게 되는 과정").
- [연구 제외]는 평가에서만 빼는 것 — 삭제 버튼은 설계상 존재하지 않습니다.

### ⑤ 오답노트 `/mistakes`
**언제**: 진화 실행 전 현황 파악. **무엇을**: 혼동 행렬 + 상태별 민감도/특이도 + 오답 bin 목록.
- 빨간 숫자(대각선 밖)와 85% 미만 지표가 "이번 세대의 표적"입니다.
- [이 오답노트로 진화 실행] 이 다음 단계로 가는 문.

### ⑥ 진화 실행 `/evolve`
**언제**: 정답지 ≥10 이고 오답 패턴이 보일 때. **무엇을**: 세대 1회 실행과 제안 검토.
- 단계: COLLECT(증거 수집) → PROPOSE(AI 제안, 3~8분) → **REVIEW_DIFF(사람 검토)** →
  REGISTERED → EVALUATING(게이트 시험) → PASSED/REJECTED.
- REVIEW_DIFF 에서 읽을 것: **변경 표**(키/현재→제안/근거), **자가시험**(train before→after),
  리스크. 납득되면 [후보 등록], 아니면 [폐기].
- 화면을 닫아도 진행됩니다 — 상태는 저장되어 재접속 시 이어집니다.
- FAILED = 3회 재시도 후 실패. 원문을 열어 원인 확인 → [정리] → 재실행.

### ⑦ 성적표 `/report` — 채택 버튼이 있는 유일한 곳
**언제**: 게이트 통과(PASSED) 후. **무엇을**: train/holdout before→after 검토와 [채택].
- **holdout 표를 보세요** — AI 가 못 본 데이터의 성적이 진짜 실력입니다.
- [채택] = 전 세션 재채점 + 새 기준 즉시 적용. 확인 모달을 거치며, 미통과 후보는 버튼이
  꺼져 있고 서버도 거부합니다(이중 방어).

### ⑧ 세대 이력 `/generations`
**언제**: 이력 확인·문서화·롤백. **무엇을**: 계보 트리 + 세대 상세(diff·성적·에이전트 원문).
- [🖨 인쇄 뷰] = 그대로 임상 문서. 프롬프트·응답 원문까지 포함되어 "AI 가 무엇을 보고
  무엇을 제안했나"를 재현할 수 있습니다.
- [롤백] = 활성 세대에서 2단 확인 → 직전 기준 원복 + 재채점.

### 설정 `/settings`
- 에이전트 기본값/타임아웃/일일 상한 · 트리거 N · **자동 제안 모드**(opt-in — 그래도 채택은 수동)
- 프로토콜 프리셋 편집(`라벨,초,지시문` 한 줄씩) · 세션 필터(임상 전환 스위치)
- 서버 주소/토큰은 `.env` 파일에서만 (화면은 현황 표시 전용)

## 자주 묻는 것

**Q. 정답지 몇 개부터 의미가 있나요?** 실행 최소선은 10개. 상태 3종이 골고루 들어가도록
프리셋을 섞어 20~30개를 권합니다 (holdout 몫도 자동으로 쌓여야 게이트가 안정적).

**Q. 진화를 돌렸는데 계속 기각돼요.** 정상 과정입니다 — 기각 사유가 다음 세대의 입력이
됩니다. 3연속 기각이면 대시보드가 "레벨 2 검토"를 권고합니다.

**Q. 채택했는데 이상해요.** 세대 이력 → 활성 세대 [롤백]. 2번 클릭이면 전 세션이 직전
기준으로 재채점됩니다.

**Q. 실서버(운영팀 Docker)로는 언제 갈아타나요?** 그쪽 `/v1/evolution/*`(S5)이 열리면
`.env` 의 SERVER_URL/EVOLUTION_TOKEN 만 바꾸고 재시작 — 이 콘솔 코드는 그대로입니다.

**Q. virtual-device(가상 큐브)로도 검증 세션을 하나요?** 아직 아닙니다 — 가상 큐브의
합성 레코드에는 분류기 입력 피처가 없어 연구용 정답지 대상이 아닙니다(앱↔서버 리허설용).
가상 큐브가 웹캠 CV 실측정 모드를 갖추면 device_client 에 WS 백엔드를 추가해 연결합니다.
